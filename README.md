# 🩺 mcp-clinic

**Архитектура и реализация протокола Model Context Protocol (MCP) в клинических веб-приложениях: три паттерна интеграции инструментов.**

Учебный проект курса «Программная инженерия мультиагентных систем клинической медицины» (Университет Иннополис, осень 2026).

Единый веб-интерфейс маршрутизирует запросы к трём независимым поставщикам MCP-инструментов и визуализирует протокольный обмен JSON-RPC.

## Три источника (транспорта) MCP

| Паттерн | Сервер | Транспорт | Инструменты |
|---|---|---|---|
| 1. Изолированный локальный | `mcp_clinic.servers.stdio_server` | stdin/stdout, дочерний процесс | 5 калькуляторов + мета-инструмент |
| 2. Локальный сетевой | `mcp_clinic.servers.sse_server` | SSE, `http://127.0.0.1:8000/sse` | 6+ инструментов по нозологиям, валидация границ |
| 3. Внешний распределённый | `pubmed-mcp` (GitHub, каталог Glama.ai) | stdio-подпроцесс к внешнему пакету | PubMed, Europe PMC, OpenFDA — 17 инструментов |

Вызовы внешних инструментов идут **строго по протоколу MCP** (JSON-RPC 2.0: `initialize` → `tools/list` → `tools/call`) — прямые HTTP-запросы к API не используются.

## Клинические инструменты (собственные серверы)

- **BMI** — индекс массы тела (WHO)
- **CKD-EPI 2021** — скорость клубочковой фильтрации (race-free)
- **CHA₂DS₂-VASc** — риск инсульта при фибрилляции предсердий
- **HAS-BLED** — риск больших кровотечений
- **GCS** — шкала комы Глазго
- **`list_calculators`** — каталог методик: границы, единицы, первоисточники
- **`list_by_category`** — фильтрация по нозологиям (SSE-сервер)

## Быстрый старт

```bash
# 1. Окружение (Python 3.11/3.12)
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt          # MCP SDK 2.x (mcp>=2.3.0), pydantic, streamlit
pip install -e .                      # пакет mcp_clinic
pip install git+https://github.com/BerkayCelk/pubmed-mcp.git   # внешний сервер (Задание 3)

# 2. Сетевой MCP-сервер на порту 8000 (терминал 1)
python -m mcp_clinic.servers.sse_server

# 3. Веб-интерфейс (терминал 2)
streamlit run app.py
```

Откройте `http://localhost:8501`: селектор источника (в боковой панели) → поиск инструмента → динамическая форма из JSON-схемы → карточка результата с цветовой стратификацией риска → **инспектор JSON-RPC** (аккордеон внизу).

Проверка stdio-сервера из консоли (без веб-интерфейса):

```bash
python -m mcp_clinic.servers.stdio_server --help   # просто запуск; обмен — stdin/stdout
```

Подключение к IDE: конфигурация для Cursor — `.cursor/mcp.json` (все три источника).

## Особенности реализации

**stdio-сервер.** Логирование — строго в `sys.stderr` (`print()` в stdout запрещён: он используется под протокольный поток). Ошибки валидации Pydantic превращаются в структурированные `ToolError`.

**SSE-сервер.** Граничные условия параметров не роняют сервер: значение поджимается к физиологической границе, клиент получает предупреждение. Клиентский `Sanitizer` приводит типы (строки → числа/булевы) и подставляет безопасные умолчания; при недоступности порта — ретраи (3 попытки, нарастающая пауза).

**Внешний сервер.** Жёсткий таймаут вызова 12 с, in-memory кэш с TTL 10 минут (защита rate limits PubMed/FDA), повторный запрос отдаётся из кэша без сети.

**Интерфейс.** Форма параметров строится автоматически из JSON-схемы инструмента: числа — слайдерами с границами, перечисления — выпадающими списками, факторы риска — флажками. Приложение не падает на некорректных данных: все исключения перехватываются и отображаются как `ToolError`.

## Ограничения

- Внешние API (PubMed, OpenFDA) могут быть недоступны из некоторых сетей — интерфейс честно показывает таймаут/ошибку, не зависая.
- Кэш внешнего клиента — in-memory, живёт в рамках сессии приложения.
- Учебный проект: результаты калькуляторов — не медицинская рекомендация.

## Структура репозитория

```
mcp-clinic/
├── app.py                          # Streamlit UI + JSON-RPC инспектор
├── mcp_clinic/
│   ├── calculators.py              # формулы + Pydantic-валидация + метаданные
│   ├── servers/
│   │   ├── stdio_server.py         # Задание 1: stdio MCP-сервер
│   │   └── sse_server.py           # Задание 2: SSE MCP-сервер :8000
│   └── clients/
│       ├── base.py                 # журнал пакетов + actor (фоновый loop)
│       ├── stdio_client.py         # Задание 1: подпроцессный клиент
│       ├── sse_client.py           # Задание 2: SSE + Sanitizer + ретраи
│       └── external_client.py      # Задание 3: внешний сервер + кэш + таймауты
├── requirements.txt
├── pyproject.toml
└── .cursor/mcp.json
```
